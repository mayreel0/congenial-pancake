# 온설 v1-moderation 브랜치 병합 결정 기록

> 메모리 요약([[concurrent_moderation_work]])과 PR 기록을 대조해 재구성. 검열 엔진 자체의 설계 결정은 이미 `2026-09-05` 문서에 별도로 있고, 이 문서는 **그 브랜치를 `v1`으로 합치는 과정**만 다룸.

## 배경

답장 검열(moderation) 엔진 작업이 별도 브랜치(`v1-moderation`)와 별도 워크트리에서 `v1`과 동시에 진행되고 있었다. 이 상태에서 `v1` 쪽 작업(PR #201)을 잘못된 브랜치 기준으로 진행해 작업이 낭비된 일이 있었음.

## 결정 1: 병합 방향보다 "통합 전략"을 먼저 물어야 한다는 교훈

PR #201에서 어느 브랜치를 기준으로 작업할지 헷갈려 낭비가 발생한 뒤, 이후로는 "어느 브랜치가 기준이냐"만 확인하는 게 아니라 **"두 브랜치를 어떤 방식으로 합칠 것인가"(머지 커밋으로 합칠지, 리베이스할지, 언제 합칠지)**를 먼저 명시적으로 물어야 한다는 교훈으로 정리됨. 단순히 "어디에 커밋할까"보다 상위의 결정이 빠져 있었던 것이 근본 원인으로 파악됨.

## 결정 2: v1-moderation은 머지 커밋으로 v1에 완전히 합쳐졌다 (PR #202, 2026-09-13)

병합 후 `v1-moderation` 브랜치와 관련 워크트리는 모두 삭제. 이 병합 커밋이 `git log --merges` 기준 과거 PR들의 병합 시각을 재작성하는 부작용을 일으켜, 이후 세션(2026-09-23 문서 백필 작업)에서 "날짜 기준 정렬이 이 저장소에서는 신뢨할 수 없다"는 걸 재발견하는 계기가 됨 — `gh pr list --json mergedAt`을 대신 써야 했음.

## 참고: PR #203

병합 직후 정리 커밋(#203)이 뒤따랐으나, 이 문서를 쓰는 시점에 남아있는 메모리에는 #203의 구체적 내용에 대한 근거가 없어 세부 서술은 생략함 — 필요하면 PR 본문을 직접 확인할 것.

## 검증

- 병합 후 `v1`에서 검열 엔진 관련 테스트/전체 빌드 통과 확인.
- 브랜치·워크트리 삭제 후 잔여 참조 없음 확인.
