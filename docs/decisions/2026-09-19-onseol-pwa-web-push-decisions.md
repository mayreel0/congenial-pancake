# 온설 PWA 설치 + 웹 푸시 알림 결정 기록

## 배경

사용자가 서비스에 부족한 점을 물으며 6개 백로그 후보(PWA+웹푸시, 광고 배너, GA, 무중단 배포, 프로필 이미지, 중앙 RAG 지식베이스)를 제시. 그중 1번(PWA+웹푸시)부터 시작하기로 했다.

## 결정 1: 네이티브 앱이 아니라 PWA부터, React Native는 나중에

네이티브 vs 웹앱(PWA) vs 하이브리드를 비교하는 대화 끝에, 실사용 트래픽이 아직 적다는 이유로 **PWA를 먼저 만들고, 트래픽이나 iOS 사용자 비중이 실제로 확인되면 그때 RN으로 넘어간다**는 단계적 접근으로 합의. "앱 만들까?" 얘기가 다시 나오면 이미 PWA가 어디까지 진행됐는지부터 확인하기로 함 — RN을 먼저 꺼내지 않기로 함.

## 결정 2: 푸시 알림 문구는 일반 텍스트만, 답장 내용은 절대 포함하지 않는다

"답장이 도착했어요" 같은 고정 문구만 보내기로 확정 — 잠금화면 등 누구나 볼 수 있는 위치에 뜨는 알림에 실제 답장 내용이 노출되면 이 서비스의 익명/프라이버시 설계와 충돌한다는 이유. "나중에 설정으로 선택 가능하게"는 백로그로 미룸.

## PR #255: PWA 설치 지원

`app/manifest.ts`, 설치 자격요건만 채우는 최소 서비스워커(`public/sw.js`, fetch 핸들러 없음 — 매일 바뀌는 피드라 캐싱 전략은 별도 결정 필요), 사용자가 직접 만든 아이콘(192/512/apple-touch-icon). `maskable` purpose는 의도적으로 뺐음 — 원본 아이콘이 이미 둥근 모서리로 그려져 있어 안드로이드 마스크를 씌우면 그 모서리가 그대로 드러남.

## PR #256~#261: 웹 푸시 백엔드/프론트엔드, 그 과정에서 발견한 버그들

- **라우팅 버그**: `NotificationsModule`의 컨트롤러 등록 순서 때문에 `DELETE /notifications/push-subscriptions`가 `NotificationsController`의 `:id` 와일드카드에 먼저 매칭돼 500 에러가 났음. 실서버 curl로 재현·확인 후 컨트롤러 순서를 바꿔 수정, 유닛 테스트로는 못 잡는 종류라 회귀 테스트도 추가([[nestjs_controller_order_routing]]).
- **IDOR**: 구독 해제가 endpoint 값만으로 스코프돼 있어서 타인의 구독을 지울 수 있었음. `userId`까지 같이 확인하도록 수정.
- **base 재조정 사고**: #257(프론트엔드)의 base가 `feat/web-push-backend`였는데, #256이 v1에 먼저 머지된 뒤에도 GitHub가 base를 자동으로 재조정해주지 않아 #257이 죽은 브랜치로 머지돼버림 — v1에 프론트엔드 코드가 아예 없는 상태가 됨. 사용자가 "#257 적용된거 맞냐"고 재확인해서 발각, 정정 PR #258로 수습. 교훈은 [[stacked_pr_base_retargeting_gotcha]]에 별도 기록.
- **프로덕션 VAPID 키 누락(내 실수)**: 백엔드 env 스키마에는 VAPID 키를 추가했지만 실제 AWS 배포 파이프라인(Terraform SSM 파라미터 목록, EC2 user-data 템플릿)과 Vercel 환경변수에는 반영하지 않아 프로덕션에서 푸시가 조용히 동작하지 않았음. 사용자가 실기기로 테스트하다 "구독된 기기가 없어요"를 보고 발견 → AWS 쪽은 Terraform 코드 작성 후 사용자가 직접 `apply`(단일 EC2 인스턴스, 로드밸런서 없어 교체 시 순간 다운타임 발생하므로 반드시 사용자 승인 필요), Vercel 환경변수는 사용자가 직접 추가.
- **계정-구독 바인딩 버그 3종**: 브라우저는 계정과 무관하게 origin당 구독이 하나뿐인데, 프론트가 "브라우저에 구독이 있는지"만 보고 "지금 로그인한 계정 소유인지"는 확인하지 않았음. 그 결과 (1) 로그아웃해도 이전 계정 알림이 계속 옴, (2) 다른 계정으로 로그인하면 토글은 켜져 있는데 구독 기기가 없음, (3) 새 계정에서 토글을 끄면 이전 계정 구독이 끊김. `GET /notifications/push-subscriptions`(내 계정 소유 endpoint 목록)를 추가해 "브라우저 구독이 내 계정 것인지"를 확인하도록 바꾸고, 로그아웃 직전 구독을 해제하도록 함(PR #261).

## PR #262: 푸시 토글을 `/notifications`에서 `/settings`로 이동

알림 수신 여부는 목록 화면이 아니라 시스템 설정에 속한다는 판단.

## PR #259: 관리자 알림 테스트 기능

사용자가 실제 기기로 매번 확인하기 번거로워 요청. 이메일로 계정을 찾아 실제 `WebPushService.sendToUser` 경로로 테스트 푸시를 보내고, "알림 목록에도 남기기"(기본 꺼짐) 옵션 추가. 구현 중 `NotificationsRepository.findMine`의 `requests` INNER JOIN이 `requestId`가 없는 알림(테스트 알림)을 통째로 목록에서 지워버리는 걸 발견해 LEFT JOIN으로 수정 — 프론트도 타입별로 표시를 분기.

## 검증

- 각 PR typecheck/lint/knip/유닛테스트 전부 통과, 로컬 실서버로 실제 curl/브라우저 검증.
- 실기기에서의 "허용" 클릭 자체는 브라우저 자동화로 재현 불가 — 이 한계는 매 라운드 PR 본문에 명시하고 사용자가 직접 확인.
