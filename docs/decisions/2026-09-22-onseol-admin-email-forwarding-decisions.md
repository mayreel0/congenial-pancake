# 온설 관리자 문의 이메일(admin@onseol.com) 결정 기록

## 배경

이용약관/개인정보처리방침을 준비하며 개인정보 보호책임자 연락처가 필요해졌다. 개인 Gmail 주소를 그대로 공개하고 싶지 않아 `admin@onseol.com` 같은 도메인 주소로 받고 싶다는 요청.

## 조사한 선택지와 트레이드오프

- **ImprovMX**: 무료 플랜으로 수신 전용 전달은 되지만, 도메인에서 발신하려면 유료(월 $9~).
- **Forward Email**: 무료 플랜 있음. 단 "도메인을 만든 지 90일 안 됐으면 월 $3" 조건이 있어 이 도메인에 해당될 수 있음.
- **Gmail "Send mail as" + Resend SMTP**: 구글이 2027년 1월부터 제3자 도메인 주소의 "다른 주소로 보내기"를 지원 중단한다고 공지함 — 몇 달 안에 끊길 위험이 있는 방식이라 채택하지 않음.

## 결정: 받기만 무료로(ImprovMX), 답장은 개인 Gmail에서

`admin@onseol.com`으로 온 메일은 ImprovMX 무료 플랜으로 개인 Gmail로 전달만 받고, **답장은 도메인 주소가 아니라 개인 Gmail 주소로 나간다**는 트레이드오프를 사용자가 명시적으로 수락. 문의가 적은 지금 규모에서는 발신까지 유료로 갈 이유가 없다는 판단.

## 구현(PR #270)

- Route53 apex(`onseol.com`)에 ImprovMX가 요구한 MX(`mx1`/`mx2`)와 SPF TXT 레코드 추가.
- 적용 전 실제 Route53을 조회해 apex에 기존 MX/TXT가 없음을 확인(`_dmarc`, `resend._domainkey`만 존재) — 덮어쓰는 레코드 없음. 발신(Resend `send.`/`rsend.` 서브도메인, SES MAIL FROM)에도 영향 없음.
- **인프라 관례상 주의**: 이 시점 `terraform plan` 전체에는 이 변경과 무관한 EC2 인스턴스 교체(최신 Amazon Linux AMI 드리프트, 로드밸런서 없는 단일 인스턴스라 교체 시 순간 다운타임)가 섞여 있어, DNS 레코드 두 개만 `-target`으로 지정한 플랜을 따로 만들어 적용. 일반 `terraform apply`를 그대로 돌리면 안 됨 — AMI 드리프트 자체는 별도 이슈로 아직 미해결.

## 검증

- 사용자가 ImprovMX 대시보드에서 도메인 인증 확인, 실제로 다른 주소에서 `admin@onseol.com`으로 보낸 메일이 Gmail에 도착하는 것까지 직접 확인.

## 남은 일

- 개인정보처리방침/이용약관 문서와 웹 푸터에 이 주소를 실제로 연결하는 작업(별도 문서 참고).
- EC2 AMI 드리프트(다음 `terraform apply` 때마다 인스턴스 교체가 끼어드는 문제)는 이 PR 범위 밖으로 남음 — 고정(pin)할지 `ignore_changes`를 걸지 별도 논의 필요.
