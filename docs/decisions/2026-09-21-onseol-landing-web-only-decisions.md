# 온설 랜딩페이지 웹 전용화 + 설치 버튼 결정 기록

## 배경

설치한 앱을 열 때마다 마케팅 랜딩 페이지가 먼저 떠서 "랜딩으로 어떻게 돌아가지"라는 어색함을 일으킨다는 문제 제기(`start_url: "/"`). "앱으로 이용하기 · 준비 중"(disabled) 버튼도 실제 설치로 이어지지 않는 상태였다.

## 결정 1(Plan Mode, AskUserQuestion으로 확정): 앱 첫 화면 / iOS 설치 안내 / 푸터 내용

- 앱을 로그인 안 한 상태로 열면 랜딩이 아니라 **로그인 화면**으로 보낸다(추천안 채택 — 게스트도 글을 남길 수 있지만, 앱은 회원 중심으로 보고 로그인 화면부터 시작).
- iOS Safari는 프로그램적으로 설치 프롬프트를 못 띄우므로 "공유 → 홈 화면에 추가" **안내 대화창**으로 대신한다.
- 웹 랜딩 푸터에는 서비스 이름+저작권, 문의 이메일, 이용약관/개인정보처리방침 링크를 넣기로 함(약관 링크는 페이지가 없어 이번 라운드에서 보류 — 아래 "남은 일" 참고).

## 결정 2: "랜딩은 웹 전용 페이지"로 접근 — 앱에서는 아예 안 보이게

로고 링크, 설치 버튼 숨김, 푸터를 각각 예외 처리하는 대신, 앱 실행 상태(`isStandaloneApp()`)면 랜딩 자체를 곧바로 앱 진입 경로로 리다이렉트하는 방식을 택함. `ServiceNav`의 로고는 이미 `/today`로 연결돼 있어 일관성도 맞음.

## 결정 3(사용자가 직접 지적): "웹앱이라 고려해야 할 부분은 더 없을까? 뒤로가기 버튼이 필요하다던"

계획 단계에서 뒤로가기/상태바 같은 독립 창(PWA) 특유의 이슈를 빠뜨렸다는 지적을 받고 재점검:

- **뒤로가기**: 코드를 다시 확인해보니 상세 페이지들(`/records/requests/[id]`, `/u/[slug]/**`)에 이미 "← 내 기록", "← 남긴 고민" 같은 상위 링크가 있고, 푸시 알림의 도착지도 이 경로들이라 히스토리 없는 진입에서도 돌아갈 곳이 있음을 확인. **새 뒤로가기 버튼은 추가하지 않기로 결정** — 처음에 "돌아가는 수단이 없다"고 한 건 판단 오류였음.
- **iOS 상태바**: `appleWebApp.statusBarStyle`을 `black-translucent`에서 `default`로 변경(PR #255에서 넣었던 설정). translucent는 콘텐츠가 상태바 아래까지 올라오는데 safe-area 처리가 없어 상단 sticky 네비와 겹칠 수 있었음.
- **소셜 로그인 왕복**은 기기별 확인이 필요해 실기기 확인 항목으로만 남김.

## PR #264: 앱 진입 경로 / 설치 버튼 / 푸터 / 상태바

`manifest.ts`의 `start_url`을 `/login?returnTo=/today`로(로그인 상태면 오늘 화면, 아니면 로그인 화면). 옛 설치본이나 로그아웃 후 `/`로 가는 경로를 대비해 `StandaloneRedirect` 추가. "앱으로 이용하기 · 준비 중"을 `InstallAppButton`으로 교체(Chromium은 `beforeinstallprompt`로 실제 설치 창, iOS는 안내 대화창).

## PR #265: 설치 버튼이 아이폰에서만 보이는 버그 + iOS 오판 버그

사용자가 안드로이드 크롬 dimensions에서는 버튼이 안 뜨는 걸 발견해 보고. 두 가지 실제 버그를 찾음:

1. `beforeinstallprompt`는 문서당 한 번만 오는데, 컴포넌트가 화면에 뜬 뒤에야 리스너를 붙여서 이벤트를 놓치는 경우가 있었음 → 루트 레이아웃의 인라인 스크립트가 이벤트를 처음부터 `window`에 보관하도록 변경.
2. 이벤트가 없는 브라우저(파이어폭스, 삼성 인터넷 등)에서는 버튼 자체가 안 뜨던 것을, 이제 "브라우저 메뉴에서 설치" 안내로 대체(iOS 전용이 아니라 일반화).

같은 라운드에서 iOS 시뮬레이터(실제 iOS 18.2)로 직접 확인해 또 다른 버그 발견: **사파리 탭에서도 `navigator.standalone`이 `true`로 나와서 앱으로 오판**되고 있었음(주소창이 보이는 사파리 탭인데도). `isStandaloneApp()`을 `display-mode: standalone` 미디어 쿼리만 쓰도록 수정(`navigator.standalone`은 `matchMedia` 자체가 없는 극히 예외적인 환경에서만 fallback). 같은 시뮬레이터로 홈 화면에 추가한 앱에서는 `display-mode: standalone`이 정상적으로 `true`가 되는 것도 확인.

## 검증

- 각 PR typecheck/lint/knip/유닛테스트 통과.
- 로컬 서버로 manifest `start_url`, 푸터 노출, 인위적으로 발생시킨 `beforeinstallprompt` 이벤트로 설치 버튼 동작 확인.
- **iOS 시뮬레이터 실기기 확인(사용자 직접)**: 사파리 탭 `display-mode: standalone` → `false`(정상), 홈 화면 앱 → `true`(정상), 설치 안내 대화창의 백드롭 탭 닫힘 동작도 확인됨.
