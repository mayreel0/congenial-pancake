# 모바일 토스트 크기와 좌우 스와이프 닫기 (DEV-97)

## 배경

이슈의 Dialog 표현을 중앙 대화상자로 해석해 달력·더보기·보류·확인창을 변경했으나, 사용자는 2026-10-09T20:22:15Z 댓글에서 “달력 부분은 필요가 없는데 … 토스트를 바꾸려던 것”이라고 정정했다. 실제 대상은 첨부 화면의 “온설을 남겼어요 ×” 알림이다. 이 정정이 이전 대상 승인을 대체한다.

## 결정과 근거

- 대상은 공유 `Toast`다. 잘못 추가한 Dialog 변경·예제·테스트·전용 훅은 제거하고 원래 동작으로 복원한다.
- 모바일(640px 미만)에서는 좌우 16px 여백으로 화면 너비를 활용하며 16px 본문, 최소 44px 닫기 버튼, 하단 safe-area 여백을 적용한다. 긴 문장은 줄바꿈하고 화면 높이를 넘는 내용은 내부에서 스크롤한다. 근거: 작고 애매한 알림 크기와 터치 조작 개선이라는 원래 요구.
- 본문 또는 여백에서 시작한 좌우 80px 이상 드래그를 놓으면 닫는다. 12px 이동으로 최초 방향을 판단하며 수평 이동이 수직 이동의 두 배 이상이어야 한다. 짧은 터치·세로/대각선 시작·다중 터치·취소·500ms 길게 누르기·텍스트 선택·닫기 버튼에서 시작한 드래그는 제외한다.
- 모바일에 `touch-action: pan-y pinch-zoom`을 지정하여 수평 제스처를 구분하면서 세로 스크롤과 확대를 허용한다. 드래그 후 클릭 억제는 400ms 후 만료되어 이후 클릭을 삼키지 않는다.
- 기존 자동 닫힘(2초), 알림 종류, `role=status`, 키보드로 누를 수 있는 닫기 버튼, 데스크톱 크기와 위치를 유지한다. reduced-motion에서는 등장 전환을 끈다. 별도 라이브러리는 도입하지 않는다.
- 2026-10-09T20:41:15Z 사용자 요청에 따라 드래그 중에는 토스트 자체가 손가락의 수평 이동량만큼 움직인다. 수평 방향이 확정되기 전에는 움직이지 않으며, 임계값 미달·취소·스크롤·화면 크기 변경 시 원위치로 돌아온다. 이동 중 보간을 끄고 복귀에는 기존 CSS 전환을 사용한다. reduced-motion에서는 복귀 보간도 생략하지만 손가락을 직접 따라가는 피드백은 유지한다.
- 같은 댓글의 다크 테마 구분 요청에 따라 토스트 배경은 기존 surface 80%와 foreground 20%를 섞는다. 입력창의 surface와 다른 명도를 주면서 기존 따뜻한 색조를 유지하고, 테두리·그림자로 경계를 보강한다. 수동 테마 선택과 OS 테마 모두 기존 CSS 변수에 따라 반영된다. 모바일 첫 줄 정렬을 맞추고 데스크톱 줄 높이를 원래 20px로 명시한다.

### 라이트 모드 복원 (2026-10-10)

사용자는 2026-10-10T07:09:32Z 댓글에서 다크 모드는 개선됐으나 라이트 모드는 원래 모습이 낫다고 정정했다. 이에 위 색상 혼합·강한 그림자는 다크 테마에만 적용한다. 라이트 모드의 surface 배경, line 테두리, 작은 그림자, muted 닫기 버튼 색을 복원한다. 모바일 크기와 드래그 동작은 유지한다.

공유 `Toast.css`에서 명시적 dark와 OS dark(명시적 light 제외)를 처리하여 web/admin/Storybook에 동일하게 적용한다. 테마 전환 시 다크 스타일이 남지 않도록 다크 선택자 안에서만 재정의한다. `LightOnInput` 예제를 추가해 기존 `DarkOnInput`과 비교할 수 있게 한다. 사용자 제한에 따라 이번 CSS 수정의 실행 검증은 수행하지 않았다.

### 모바일 높이 축소 (2026-10-10)

사용자의 2026-10-10T07:19:36Z “height 를 살짝 줄일 수 있을까” 요청에 따라 모바일 토스트의 위아래 패딩을 각각 12px에서 8px로 줄인다. 한 줄 기준 CSS 계산 높이는 70px에서 62px가 된다. 닫기 버튼의 44px 터치 영역과 본문 크기·정렬을 유지하면서 여백만 줄이며, 데스크톱 패딩은 기존 12px를 유지한다. 이번 변경은 `Toast.tsx`와 이 결정 기록에 한정하며 실행 검증은 수행하지 않았다.

## 산출물

- `Toast.tsx`의 모바일 레이아웃과 `useMobileToastSwipe.ts` 연결.
- `MobileToast.test.tsx`의 방향·임계값·세로 스크롤·조작 제외·취소·텍스트 선택·교체·클릭 억제 만료 회귀 테스트 소스.
- `Toast.stories.tsx`에 실제로 닫고 다시 열 수 있는 `MobileSwipe`, `LongMessage` 예제. 자동 닫힘은 이 수동 확인용 예제에서만 적용하지 않는다.
- `DarkOnInput` 예제는 다크 테마 입력창과 토스트를 함께 표시한다. 드래그 중 위치, 짧은 드래그 후 복귀, 취소·스크롤·다중 터치·resize 복귀의 테스트 소스도 추가했다.

## 검증

사용자 제한에 따라 테스트·브라우저·실기기·검증 게이트·외부 리뷰는 실행하지 않았다. 이전 Orchestrator의 23개 검증 통과 보고는 폐기한 Dialog 구현에 대한 결과이므로 토스트 검증으로 재사용하지 않는다. 기존 서버 시작 시도는 포트 바인딩 제한으로 실패했으며 재시도하지 않았다. 커밋·푸시·PR·Linear 상태 변경은 하지 않았다.

제공된 2026-10-10T16:09:17Z Orchestrator 보고는 최종 닫기 버튼 수정 이후 Gate 1 필수 항목 23개 통과를 기록한다. 이는 폐기된 Dialog 구현의 보고와 별개이며, 이 세션에서 독립 실행하거나 재검증한 결과는 아니다.

사용자는 2026-10-10T16:04:01Z에 실기기에서 드래그와 색상에 만족한다고 밝혔고, 닫기 버튼 수정 이후 2026-10-10T16:19:17Z에 실제 모바일 기기와 스토리북에서 동작을 모두 확인했으며 UI에도 만족한다고 확인했다. 이전의 실기기·변경 후 화면 확인 대기는 이 후속 사용자 확인으로 해소한다. 상세 기기 정보나 스크린리더·가상 키보드 등 개별 항목별 결과는 제공되지 않았으므로 별도의 개별 통과 기록을 만들지는 않는다. 닫기 버튼 변경 및 확인 근거는 `2026-10-11-onseol-mobile-toast-close-decisions.md`에 기록했다.

## 남은 일

사용자 확인 이후 남은 구현 요청이나 사용자 결정은 없다. 추가 동작 변경 없이 현재 구현을 유지한다. 기존 2초 자동 닫힘은 터치 중에도 계속 적용된다.

직접 확인할 경우 워크트리의 `apps/storybook-app`에서 설치된 실행 파일로 시작한다:

```sh
STORYBOOK_DISABLE_TELEMETRY=1 ./node_modules/.bin/storybook dev -p 6006 --host 0.0.0.0 --ci --no-open --disable-telemetry
```

`http://localhost:6006/iframe.html?id=shared-toast--mobile-swipe&viewMode=story`에서 확인한다. 휴대폰은 동일 Wi-Fi에서 localhost 대신 실행 컴퓨터의 LAN IP를 사용한다. 서버 종료는 Ctrl+C다.
