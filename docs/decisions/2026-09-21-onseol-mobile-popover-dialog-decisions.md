# 온설 모바일 팝오버 → 다이얼로그 전환 결정 기록

## 배경

iOS 시뮬레이터로 앱 환경을 직접 조작해보던 중 사용자가 세 가지 불편을 지적:

- 보류 패널(`/answer`)을 열었을 때 뜨는 내용 영역이 애매함.
- 신고하기/삭제하기가 뜨는 3점 메뉴(`ui/MoreMenu`)가 모바일, 특히 앱 환경에서 너무 작고 눈에 안 띔 — "갤럭시에서 select 눌렀을 때처럼 dialog 같은 형식에 배경은 검게 되는 UI 형태가 좋을 것 같음."
- `HeatmapCalendarField`(날짜 선택 팝오버)도 같은 형태가 좋겠고, 특히 `/records`의 종료일 필드는 누르면 화면 밖으로 넘어가 페이지 너비 자체가 확장되는 버그가 있음.

## 결정 1: 640px 미만(모바일 폭)에서만 중앙 다이얼로그로, 데스크톱은 기존 팝오버 유지

앱 여부가 아니라 **화면 너비** 기준으로 나누기로 함 — 모바일 브라우저 탭에서도 똑같이 작아서 불편하기 때문. 전환은 CSS(`sm:contents`)만으로 처리해 JS 너비 감지·하이드레이션 불일치를 피함.

## 결정 2: 다이얼로그에 눈에 보이는 제목은 굳이 안 붙인다

"다이얼로그처럼 꼭 제목을 붙일 필요는 없음" — 접근성 이름(`aria-label`)만 붙이고 화면에는 항목만 보여줌.

## 결정 3: 보류 패널은 데스크톱에서도 그대로 팝오버로 둔다

세 번째(보류 패널) PR 이후, 데스크톱에서도 다이얼로그로 통일할지 물었으나 — 보류 패널은 "대화 흐름을 보면서 가볍게 고르는" 용도라 화면을 가리는 다이얼로그가 과하다는 의견을 제시했고, 사용자가 "지금 그대로 두자"고 확정. 다만 288×288px 미리보기가 좁다는 점은 필요해지면 별도로 키우는 걸로 남김.

## 구현: 공통 `PopoverDialog` 컴포넌트(`packages/ui`)

세 곳(달력, 3점 메뉴, 보류 패널)이 같은 동작이 필요해서 처음부터 공유 컴포넌트로 만듦([[feature_then_extract_shared_component]]과 달리 이번엔 세 사용처가 동시에 확정돼 있어 예외적으로 먼저 추출). `packages/ui`라 admin 앱의 날짜 필드/메뉴도 함께 적용됨.

- **PR #266**: `PopoverDialog` 신설 + `HeatmapCalendarField` 적용. 종료일이 화면 밖으로 넘어가던 오버플로 버그가 이걸로 함께 해결됨.
- **PR #267**: `MoreMenu` 적용, 모바일 눌림 영역을 24px → 40px로 확대(음수 마진으로 데스크톱 레이아웃은 유지).
- **PR #268**: `HoldPanel` 적용, 최대 높이 `70dvh`.

리뷰를 거치며 `PopoverDialog` 자체에 실제 버그가 몇 개 더 발견돼 고쳐짐: 닫히는 애니메이션 동안 `aria-hidden` 처리(안 하면 닫히는 중인 요소가 곧바로 뜨는 확인 다이얼로그와 `role=dialog` 조회가 겹침), 닫히는 동안 `pointer-events-none`(안 하면 `z-40` 레이어가 바로 뒤에 뜨는 확인 다이얼로그로 가는 탭을 가로챔), iOS에서 배경 탭이 씹히는 문제(빈 `div`엔 iOS가 클릭 이벤트를 안 보냄 → `cursor-pointer`로 우회), `ActionConfirmDialog`의 `z-30`이 `PopoverDialog`의 `z-40`보다 낮아 계층이 역전돼 있던 것(`z-50`으로 조정).

## 회귀: 보류 버튼이 프로필 메뉴를 가림(PR #269)

PR #268에서 보류 패널의 모바일 다이얼로그 배경이 상단 헤더까지 덮이게 하려고 버튼 래퍼를 `z-10`→`z-30`으로 올렸는데, 이게 **패널이 닫혀 있을 때도** 적용돼서 보류 버튼이 프로필 메뉴 드롭다운 위에 그려지는 회귀가 생김. 사용자가 실사용 중 직접 발견("보류중 버튼이 프로필 메뉴보다 앞에 나와있어서 가리네"). 패널이 열려 있는 동안(닫히는 애니메이션이 끝날 때까지 포함)에만 `z-30`, 그 외에는 `z-10`으로 되돌림.

## 검증

- 각 PR typecheck/lint/knip/유닛테스트 통과.
- 390px 폭 iframe으로 세 컴포넌트 모두 모바일 형태(중앙 다이얼로그, 가로 스크롤 없음, 배경 탭/Escape/버튼으로 닫힘) 확인, 900px 폭에서 기존 팝오버 위치·크기 동일함도 확인.
- #269 회귀 수정 후 프로필 메뉴와 겹치는 지점의 최상단 요소가 실제로 프로필 메뉴인지 좌표 기반으로 확인.

## 남은 일

- 다이얼로그가 떠 있는 동안 뒤 화면 스크롤 잠금은 범위 밖으로 명시적으로 제외.
- 보류 패널을 데스크톱에서 더 크게 보여줄지는 결정 3에서 보류.
