# 온설 CI + knip 도입 결정 기록

> 메모리 요약([[ci_and_knip_setup]])과 PR 기록을 대조해 재구성.

## 배경

PR #182/#183/#184 (이 순서로 의존) — 이전까지 이 저장소엔 실질적인 CI 게이트가 없었음. knip(미사용 export/파일 탐지 도구)을 붙이면서 동시에 첫 실질 CI 체크를 도입.

## 결정 1: knip은 처음엔 non-blocking으로 둔다

기존 코드베이스에 knip이 잡아내는 미사용 항목이 상당히 있어서, 이를 전부 정리하기 전까지는 CI 실패로 막지 않고 경고만 내는 방식으로 시작. (이후 정리 PR들 — 예: `ReplyComposer.tsx` 죽은 코드 제거가 PR #186에서 처리, [[ux_overhaul_backlog]] 참고.)

## 결정 2: 이 CI 도입 과정 자체가 실제 버그를 하나 잡아냈다

`formatTimestamp`류 유틸이 KST 타임존 처리에서 실제로 잘못된 값을 내고 있었는데, CI를 새로 돌리는 과정에서 이 버그가 드러나 함께 수정됨 — CI 자체의 가치를 보여준 사례로 메모리에 남아있음.

## 검증

- PR #182/#183/#184 각각 typecheck/lint/유닛테스트 통과 + 새 CI 워크플로 자체가 통과하는지 확인.
- KST 버그는 실제 재현 테스트 케이스로 확인 후 수정.
