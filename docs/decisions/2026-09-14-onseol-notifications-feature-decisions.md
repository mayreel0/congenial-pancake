# 온설 알림 기능(SSE/배지/딥링크) 결정 기록

> 메모리 요약([[notification_feature_backlog]])과 PR 기록을 대조해 재구성. PR #219–#225 전체가 이 기능 하나로 이어지는 시리즈.

## 배경

답장이 달렸을 때 알림을 받을 방법이 전혀 없던 것을 계기로, 인앱 알림 기능 전체(생성 → 실시간 전달 → 배지 → 목록 → 딥링크)를 여러 PR로 나눠 진행.

## 범위(PR #219–#225)

- 알림 생성(답장 발생 시 서버에서 레코드 생성)
- SSE(Server-Sent Events)로 실시간 전달
- 헤더의 안 읽음 배지
- `/notifications` 목록 페이지
- 알림 클릭 시 해당 글/답장으로 딥링크 이동

이 시리즈가 완료된 뒤, 이후 라운드(PR #253/#254, `2026-09-17` 문서 참고)에서 개별/전체 삭제 기능이 추가됨. 웹 푸시(브라우저 알림)는 별도 완전히 분리된 후속 라운드(`2026-09-19-onseol-pwa-web-push-decisions.md`)로 진행됨 — 이 시리즈는 **인앱 알림**만 다룸.

## 교훈: "습관적으로 git checkout v1"이 만든 허위 버그 보고

작업 중 습관적으로 `git checkout v1`을 실행했다가, 실제로는 문제 없는 코드를 마치 SSE가 끊기는 버그가 있는 것처럼 잘못 보고한 사례가 있었음. 원인은 코드 문제가 아니라 **작업 디렉터리를 다른 브랜치로 옮겨버린 것** — 같은 작업 디렉터리를 사용자가 라이브 테스트에 쓰고 있는 상태에서 브랜치를 이동하면, 실제로는 죽지 않은 기능이 죽은 것처럼 보일 수 있다는 교훈으로 남음. 이후 공유 작업 디렉터리에서는 푸시 직후 임의로 브랜치를 벗어나지 않는 습관으로 이어짐([[shared_workdir_branch_switch_risk]]).

## 검증

- 각 PR typecheck/lint/유닛테스트 통과.
- SSE 연결 실서버로 실시간 도착 확인, 배지 카운트 증감 확인.
- 딥링크는 실제 알림 클릭 → 목적 페이지 도달까지 확인.
