# 온설 /records 탭 분리 결정 기록

## 배경

PR #101(백엔드 `GET /requests/mine`) 머지 후 PR #102(프론트, `/records`에 "내가 남긴 고민" 섹션 추가)가 리뷰 중인 상태에서 사용자 피드백: "받은거랑 남긴거랑 한페이지에 다 있으니까 너무 길어지는데 ... 받은거랑 남긴거는 나눌 수 있는 방법이 있어야 할 것 같아. Tabs 컴포넌트라던가 페이지를 나눈다던가." 추후 페이지네이션/인피니티 스크롤도 섹션별로 붙일 계획이라고 함께 언급.

## 결정: 한 페이지 + Tabs

옵션(한 페이지+Tabs / `/records`·`/records/replies`로 라우트 분리) 중 "한 페이지 + Tabs(추천)"로 확정.

- `/records`는 그대로 하나의 진입점으로 남고, 그 안에서 탭("내가 남긴 고민"/"내가 남긴 답변")으로 전환.
- 현재 활성 탭의 섹션만 마운트되므로 비활성 탭의 쿼리는 아예 실행되지 않음 — 초기 로딩이 가벼워짐.
- 추후 탭별로 독립적인 페이지네이션/인피니티 스크롤을 붙이기에도 자연스러움(각 탭이 별도 마운트/언마운트되므로 스크롤 컨테이너도 독립적).
- 라우트를 늘리지 않아 `accountNavItems`(내 정보/내 기록)에 하위 네비게이션을 추가로 얹지 않아도 됨 — 기존 IA와 일관.

## 산출물

- `packages/ui`가 아니라 `apps/web/app/records/components/RecordsTabs.tsx`에 로컬로 구현 — 아직 이 한 곳에서만 쓰이므로 공용 컴포넌트로 미리 뽑지 않음(기능 먼저, 추출은 나중이라는 기존 원칙과 동일).
- `RecordsPageContent.tsx` 신설(클라이언트 컴포넌트, `useSearchParams`/`useRouter` 사용) — `page.tsx`는 서버 컴포넌트로 얇게 남기고 `<Suspense>`로 감쌈. `useSearchParams`를 쓰는 컴포넌트는 정적 렌더링을 위해 Suspense 경계가 필요하다는, 이미 `reset-password/page.tsx`가 쓰던 패턴을 그대로 따름.
- 활성 탭은 `?tab=` 쿼리 파라미터에서 최초 1회 시드해서 로컬 `useState`로 관리 — 공유/북마크 가능하도록 URL도 같이 갱신하지만, 렌더링 자체는 state에만 의존(라우터가 실제로 왕복하지 않는 테스트 환경에서도 탭 전환이 정상 동작하도록).
- `MyRequestLogSection`/`MyAnswerLogSection` 컴포넌트 자체는 변경 없음(여전히 `useAuth()`/쿼리 훅을 스스로 호출하는 self-contained 패턴) — 부모가 조건부로 마운트/언마운트만 함.

## 검증

- `apps/web` lint/typecheck/test(76/76)/build 통과.
- 실브라우저 검증: `/records`에서 기본 탭("내가 남긴 고민")과 전환한 탭("내가 남긴 답변") 각각 올바른 내용만 보이는 것, 탭 전환 시 이전 탭 내용이 사라지는 것 확인.
