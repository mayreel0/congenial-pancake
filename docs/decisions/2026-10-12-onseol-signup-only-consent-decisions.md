# 온설 가입 동의 위치 수정

## 배경

DEV-38 사용자 피드백: 로그인 화면의 동의 체크박스가 이미 가입한 회원의 소셜 로그인도 막고 있어 잘못된 배치라는 지적을 받았다. 기존 승인된 약관·처리방침과 필수 가입 동의는 유지하면서 이 흐름을 수정한다.

## 결정과 근거

- 로그인 화면에는 가입 동의를 표시하지 않는다. 이메일·소셜 기존 회원은 동의 없이 로그인한다.
- 가입 화면과 이메일 인증 후 가입 완료 화면에서 필수 동의를 받는다.
- 소셜 로그인에서 계정이 없으면 생성·세션 발급 없이 가입 화면으로 안내한다. 사용자는 동의 후 소셜 계정을 다시 선택한다.
- 가입 화면에서 시작한 OAuth 요청만 가입 의도를 포함한다. 이 의도는 서버가 생성한 state와 쿠키의 일치 확인에 묶어 콜백의 별도 쿼리로 변경되지 않게 한다.
- 기존 소셜 연결 계정과 인증된 이메일 계정 병합, 로그인 상태에서의 제공자 연결은 유지한다. 미인증 과거 계정 활성화에는 가입 흐름을 요구한다.

근거: 기존 회원에게 가입 동의를 반복 요구하지 않으면서 로그인 버튼을 통한 무동의 신규 계정 생성을 막아야 한다. 별도 임시 프로필 저장 체계를 추가하지 않고 기존 OAuth 흐름을 사용한다.

2026-10-13 KST 사용자 최종 확인: “확실히 로그인 페이지엔 동의 토글이 없는게 맞네. 이렇게 확정할게 그냥” (제공된 댓글 시각: 2026-10-12T16:58:21.032Z). 현재 로그인·가입 동의 배치를 유지한다.

## 산출물

- LoginForm: 로그인 동의 제거, 가입 모드 복귀 안내.
- OAuth URL: 가입 경로만 signup=true 전달.
- AuthController/AuthService: 검증된 state로 가입 의도를 전달하고 일반 로그인에서 신규 생성 차단.
- 프론트·서비스·컨트롤러 회귀 테스트 추가/수정.

## 검증

소스와 변경 내용을 확인했다. 제공된 2026-10-12 Orchestrator 결과에는 필수 검증 23개 통과와 독립 소스 리뷰 승인(Gate 2)이 기록되어 있다. 이는 전달받은 결과이며, 이번 작업에서 테스트나 검증 게이트를 재실행하지 않았다. 실제 브라우저·OAuth 제공자 왕복 검증은 수행된 것으로 확인되지 않았다. 사용자는 이후 로그인 화면에 동의 토글이 없음을 확인하고 현재 배치를 확정했다.

## 남은 일

구현 차단 사항 없음. 동의 이력의 서버 저장은 이번 구현에 포함하지 않는다. 기존 문서의 공개 전 운영 정보 확정 항목과 초안 표시는 유지한다.
