# 온설 localStorage 프로토타입 설계 기록

## 배경

- 사용자는 Storybook을 먼저 도입하기보다, 간단한 localStorage 프로토타입을 만들어 실제 흐름을 본 뒤 Storybook으로 컴포넌트를 분리하는 방향을 제안했다.
- 이 방향은 온설에 적합하다고 판단했다.
- 이유는 아직 실제 요청 작성, 답변 작성, 내 활동 확인 흐름이 없기 때문에 Storybook만 먼저 만들면 필요한 컴포넌트가 추상적으로 정해질 위험이 있기 때문이다.

## 결정

- 다음 단계는 localStorage 앱 프로토타입 설계 문서 PR로 진행한다.
- 프로토타입 구현은 별도 PR에서 진행한다.
- Storybook은 프로토타입 리뷰 후 도입한다.
- Storybook에는 프로토타입에서 실제로 확인된 컴포넌트를 분리한다.

## 추천한 범위

- `/today` route 후보
- 요청 작성 draft localStorage 저장
- 답변 작성 draft localStorage 저장
- 요청 제출과 답변 제출
- 한 브라우저 사용자 기준 한 요청에 답변 1개
- 답변 부족 요청 우선 노출
- 최근 요청/답변 표시
- 신고/필터 stub
- 내 요청과 내 답변 간단 확인

## 제외한 범위

- 실제 로그인
- Nest.js 백엔드
- 데이터베이스
- 서버 기반 신고/필터
- 실제 AI 안전 필터
- 자동 댓글 생성
- 앱 알림
- 시즌 이벤트와 활동 시각화

## 위키 이전 포인트

- Storybook을 먼저 도입하는 방식보다 프로토타입을 먼저 만드는 방식이 현재 온설에는 더 적합하다.
- 이유는 온설의 핵심 문제가 컴포넌트의 외형보다 사용 흐름과 서비스 감각에 있기 때문이다.
- 프로토타입은 완성 UI가 아니라 흐름 검증용이어야 한다.
- 프로토타입에서 나온 반복 컴포넌트를 Storybook으로 분리하면 더 실제적인 디자인 시스템 검증이 가능하다.
- route, 샘플 데이터, 데이터 초기화 버튼, 데스크톱 레이아웃, 신고 숨김 방식은 구현 전 사용자 확인이 필요하다.
