# DEV-98 모바일 개발 백엔드 연결 조사

## 상태

**구현 완료 — 관리 세션 실측 반영(2026-10-22 KST):** 최신 2026-10-21 20:10 UTC 보고에서
Android 실기기의 LAN/Tailscale web 로그인·세션·UI 글쓰기와 개발 DB 저장, admin 화면·
공유 세션·로그아웃, Storybook 표시, API 직접 접근 거부, localhost HTTP/API 회귀와
테스트 자원 원복을 확인했다. WAN 포워딩 제거는 사용자 확인이다. 확인된 설정·실기기 결과의
재제출을 요청하지 않는다. 이전 차단 상태는 이 보고로 해소되었으며 아래 기록은 당시의 이력이다.
정확한 범위와 미검증 항목은 `docs/development-vpn.md`에 기록했다. Wi-Fi 상태의 Tailscale
시험을 셀룰러 단독 시험으로, HTTP/API 회귀를 데스크톱 UI 시험으로 확대하지 않는다.
이번 재개에서는 문서 3개만 갱신하고 기존 코드·비공개 설정을 보존했다. worker의 5/5 테스트
성공과 pnpm/adb 실행 거부는 별도 증거로 유지하며 차단된 명령을 재시도하지 않았다.
후속 게이트·리뷰·PR·Human Review는 Orchestrator에 넘긴다. 실행·통과·병합을 주장하지 않는다.

**이전 설정 적용 보고 반영(2026-10-22):** 제공된 2026-10-21 19:17 UTC 댓글에서 API `.env`와
web/admin `.env.development.local` 적용을 확인했다. 실제 `validateEnv`에서 development,
loopback DB, 호스트 2개, `/api`, Origin 7개를 확인했다는 관리 세션의 결과다.
기존 자격증명 보존, 권한 600, Git ignore 확인도 보고되었다. Agent는 비밀파일에 접근하지 않았다.
이로써 아래 이전 기록의 환경파일 적용 차단은 해소되었다. 재적용·정책 해제를 요청하지 않는다.
frontend 개발 전용 파일명을 실행 안내와 두 `.env.example`에서 바로잡았다.
기존 프록시 테스트 5개 통과 및 pnpm/adb 실행 거부 기록은 그대로 유지한다.
그 당시 휴대폰·VPN·방화벽 기능 검증은 미수행이었으며 Human Review에서 확인할지에 대한
사용자 답변도 제공되지 않아 미완료 수용 조건으로 기록했다. 최신 상태는 위 실측 반영을 따른다.

**2026-10-22 재개:** 최신 요청은 제공한 기존 환경파일을 예시에 맞춰 정리하는 것이다.
이번 실행의 실제 `.env`/`.env.local` 읽기 금지 정책 때문에 해당 파일은 읽거나 변경하지
않았다. 비밀값을 우회해 수집하거나 기존 파일을 덮어쓰지 않았다. 환경파일 정리 항목을
`docs/development-vpn.md`에 추가했다. 당시에는 사용자 로컬 적용 확인과 실기기 결과가 필요했다.
프록시 설정 테스트는 5/5 통과했다. API 테스트의 `pnpm`은 exit 126/`Operation not permitted`,
`adb devices -l`은 exit 127/`zsh:1: operation not permitted: adb`로 실행이 차단됐다.
정확한 명령·오류는 실행 안내의 2026-10-22 표에 기록했다. 기기 목록은 얻지 못했으므로
연결·인증 상태를 추정하지 않는다. 테스트/기기 작업 자체의 금지는 아니며 재승인을 요청하지 않는다.

**2026-10-12 갱신:** 아래는 최초 조사 당시 기록이다. 사용자 후속 댓글로 프록시 방식,
L2TP/IPsec VPN 내부 접근, WAN 포워딩 제거와 개발 API/DB 분리가 확인되었다.
구현과 확정 결정은 `docs/decisions/2026-10-12-onseol-mobile-vpn-proxy-decisions.md`,
실행·종료 및 미검증 항목은 `docs/development-vpn.md`를 따른다.
이전의 연결 방식 승인 요청은 해소되었으며 실제 네트워크 설정·실기기 확인은 남아 있다.

**후속 보고 반영:** 사용자가 갤럭시의 Tailscale 접속과 아이폰의 LAN 접속에서 백엔드 결과가
나오지 않았다고 보고했다. 함께 제공된 진단에서는 DEV-97 web/API가 실행 중이었고,
DEV-98의 프록시는 사용되지 않았다. 목적지의 PC Tailscale 주소 소유 여부와 실제 요청 URL,
HTTP 상태는 미확인이다. 이 작업에서 프로세스나 외부 기기를 재점검·종료·재시작하지 않았다.
DEV-98 설정의 Tailscale 주소 거부는 코드에서 확인하고 보완했다. 기본/추가 호스트를 환경변수로
지정해 LAN·Tailscale의 정확한 Origin을 허용하며 기존 보안 검사를 유지한다.
실행 안내에 올바른 워크트리, 포트 점유, 동시 인터페이스 바인딩 조건, 주소별 세션과
주소 변경 시 설정 갱신 절차를 추가했다. 회귀 테스트는 보완했으나 실행하지 않았다.

최초 조사 시점에는 연결 방식과 외부 테스트 접근 제한에 대한 사용자 결정을 기다렸고 구현하지 않았다.
당시 제공된 작업 데이터에 댓글 이력이나 승인된 연결 방식은 없었다. 이미지 입력도 없었다.
최초 작업은 워크트리 파일 조사만 수행했다. 외부 연동, 서버 실행, 검증 게이트,
공유기·DNS 변경, Linear 상태 변경, 커밋·푸시는 수행하지 않았다.

## 확인한 코드와 실패 가설

- `packages/api/src/index.ts`: `NEXT_PUBLIC_API_BASE_URL`이 없으면
  `http://localhost:8080`으로 요청한다. `apps/web/.env.example`도 같은 값이다.
  모바일에서 이 값은 개발 머신이 아닌 모바일 자신을 가리킨다.
  실제 실행 중인 프론트엔드의 환경변수와 요청 URL은 확인하지 못했으므로
  사용자 보고의 실제 원인으로 확정하지 않는다.
- `apps/web/next.config.ts`: 보고된 외부 호스트는 이미 `allowedDevOrigins`에
  포함되어 있다. API 프록시 설정은 없다. 이 허용 설정은 백엔드 CORS 설정을
  대신하지 않으며 외부 사용자의 접근을 제한하는 인증 수단도 아니다.
- `apps/api-server/src/main.ts`: 호스트를 지정하지 않고 포트만 지정해 listen한다.
  루프백 전용 바인딩을 코드로 보장하지 않는다. 실제 방화벽·포트포워딩 상태는 미확인이다.
- `apps/api-server/.env.example`: CORS 허용 목록은 로컬 web/admin/Swagger 주소다.
  `csrf-origin.middleware.ts`도 이 목록으로 Origin/Referer를 검사한다.
  프록시 도입 시에도 모바일 페이지의 정확한 Origin을 개발 설정에서 허용해야 한다.
  Origin 검사를 제거하거나 무조건 로컬 Origin으로 바꿔 전달하는 방식을 사용하지 않는다.
- `common/cookie-options.ts`: HttpOnly, SameSite=Lax이며 Secure는 운영에서만 true다.
  개발 HTTP 세션을 위해 운영 쿠키를 변경할 필요는 없다. HTTP는 세션·비밀번호를
  암호화하지 않으므로 테스트 전용 계정·데이터와 네트워크 접근 제한이 필요하다.
- `config/env.schema.ts`: `DATABASE_URL`은 URL 형식만 검사한다. 예시가 로컬 Postgres라는
  사실만으로 실제 개발 DB와 운영 DB의 분리를 보장할 수 없다.
- OAuth는 `API_PUBLIC_URL`, `WEB_PUBLIC_URL`에 의존한다. 프록시 경로를 반영한 callback과
  제공자 콘솔 등록도 필요하며, 이메일 로그인 성공만으로 OAuth 성공을 주장할 수 없다.
- `apps/web/app/lib/notifications/useNotificationStream.ts`는 같은 API base로 SSE를 연다.
  프록시는 일반 JSON 요청 외에도 쿠키와 SSE 스트리밍을 보존해야 한다.

기존 인증 결정과 2026-09-24 쿠키 결정에 따라 운영 SameSite=Lax, Secure=true 및
CSRF Origin 검사를 유지하는 것이 전제다.

## 사용자에게 제안할 결정 — 아직 승인되지 않음

**권장: 명시적으로 켜는 개발 전용 동일 Origin API 프록시.**

- 모바일 브라우저는 web의 상대 경로 `/api`를 호출하고, web 서버만
  `http://127.0.0.1:8080`의 개발 API에 연결한다.
- 프록시는 개발 모드에서만 활성화하고 운영 API나 임의 외부 upstream을 허용하지 않는다.
  기본 데스크톱 개발 방식은 유지한다.
- API는 이 개발 모드에서 루프백에 바인딩한다. DB, admin, Swagger 포트를 추가로 공개하지
  않으며 프록시에서도 관리자 API와 문서 경로를 공개하지 않는다.
- 개발 환경의 정확한 외부 Origin만 추가한다. 운영 보안 설정은 그대로 둔다.
- 외부 HTTP 테스트는 테스트 전용 계정·데이터로 한정하고, 기존 3000 포워딩에
  테스트 기기만 들어올 수 있는 공유기/방화벽 접근 제한을 적용하는 방안을 제안한다.
  해당 제한을 사용할 수 없다면 VPN 또는 HTTPS와 접근 인증 방식부터 별도로 확정한다.
  HTTP Basic 인증만으로 암호화 문제를 해결했다고 취급하지 않는다.

추가 8080 포워딩보다 공개 포트를 줄이고 브라우저의 교차 Origin 쿠키 문제를 피할 수 있다.
다만 프록시 자체로 web이나 개발 소스 접근이 제한되지는 않는다.

**필요한 사용자 응답:** 위 개발 전용 프록시 방식 승인 여부와 기존 3000 포워딩에
테스트 기기 접근 제한을 적용할 수 있는지 알려주어야 한다. 적용할 수 없다면
VPN 또는 HTTPS+접근 인증 중 사용할 환경을 지정해야 한다.
실제 개발 API/DB가 운영과 분리되어 있다는 확인도 필요하다. 비밀번호·토큰·전체 DB URL은
제공하지 않는다. 이 결정을 해결한 댓글이 있다면 해당 댓글 내용을 제공하면 된다.

## 결정 후 구현·실행 안내에 포함할 항목

- 개발 전용 활성화 변수와 상대 API base, 정확한 CORS Origin,
  API/WEB public URL의 설정 예시. 실제 호스트와 시크릿은 기록하지 않는다.
- 개발 DB 대상 확인 후 API와 web 실행 명령, 기존 데스크톱 환경으로 복귀하는 방법.
- 테스트 종료 시 서버 프로세스 종료, 기존 3000 포워딩 비활성화,
  임시 접근 규칙 제거 및 테스트 세션 로그아웃 절차.

## 검증 상태

코드 조사만 수행했다. 단위 테스트, 서버/curl, 브라우저, 모바일 실기기 검증은 수행하지 않았다.
연결 방식 확정 및 구현 후 사용자가 다음을 확인해야 한다:

- 모바일 데이터 조회, 로그인 → 새로고침 → 세션 유지 → 로그아웃.
- 비회원 쿠키 유지, 주요 쓰기 흐름, SSE 연결, 사용하는 OAuth 제공자의 callback.
- 모바일 요청에 localhost나 운영 API가 없고 실제 데이터가 개발 DB에만 기록되는지.
- 기존 데스크톱 흐름과 운영 설정 유지, 외부에서 DB/admin/Swagger 접근 차단.
- 테스트 접근 제한 및 테스트 종료 후 외부 접속 차단.

이 항목들은 현재 이슈의 완료 조건이며 별도 Backlog 작업으로 넘기지 않는다.
