# Onseol Next Boilerplate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Create the minimal Next.js, React, TypeScript, and Tailwind CSS boilerplate needed before the 온설 landing page implementation starts.

**Architecture:** This PR creates only the application shell and verification baseline. It must not implement the 랜딩 UI, localStorage prototype, auth simulation, backend, or `/today` route. The project starts as a single Next.js app at the repository root so Vercel can deploy it directly later.

**Tech Stack:** Next.js App Router, React, TypeScript, Tailwind CSS, ESLint, pnpm.

## Global Constraints

- Work from a new worktree and a non-protected branch; do not commit directly to `main` or `v1`.
- Keep this PR limited to boilerplate: no 온설 landing content beyond default metadata placeholders and no interactive service flow.
- Do not introduce Supabase, Nest.js, database code, auth code, AI filtering, localStorage persistence, or `/today`.
- Use Node.js 22 or newer.
- Use pnpm as the package manager.
- Pin the project package manager with Corepack using `corepack use pnpm@latest-11`.
- Use official-documentation `latest` package resolution for Next.js, React, and Tailwind CSS, then rely on `pnpm-lock.yaml` to record the exact resolved versions.
- Use TypeScript from the start.
- Use Tailwind CSS from the start because the approved product direction chose Tailwind for the frontend.
- Verification must include install, lint, typecheck, build, and a local render smoke check.

## File Structure

- Create: `package.json` for pnpm scripts, dependencies, and `packageManager`.
- Create: `pnpm-lock.yaml` generated by pnpm install.
- Create: `next.config.ts` for the Next.js config.
- Create: `tsconfig.json` for TypeScript configuration.

- Create: `postcss.config.mjs` for Tailwind processing.
- Create: `app/layout.tsx` for the root HTML shell and metadata placeholder.
- Create: `app/page.tsx` for the default root route placeholder.

- Create or update: `.gitignore` for Next.js, Node, env, and local build artifacts.
- Modify: `README.md` to include the basic local setup commands.

This structure intentionally avoids feature folders and domain modules. Those belong to the later landing and localStorage prototype PRs.
