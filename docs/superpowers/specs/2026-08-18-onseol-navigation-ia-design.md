# 온설 네비게이션 IA 스펙

## 목적

온설은 랜딩 페이지와 실제 서비스 화면의 역할이 다르다. 랜딩은 서비스를 처음 만나는 사용자가 웹에서 바로 시작할지, 로그인해서 이어갈지 선택하는 진입면이다. 서비스 화면은 이미 온설을 이용 중인 사용자가 `남기기`, `답하기`, `온설 읽기`, `내 기록` 사이를 이동하는 작업면이다.

이번 문서는 랜딩 네비게이션과 서비스 네비게이션을 분리하고, 웹과 모바일에서 어떤 이동 방식을 사용할지 정한다. 이 문서는 #45의 `/today` 구현에 직접 의존하지 않는다. 이후 구현은 실제 merge된 `v1` 상태를 기준으로 별도 PR에서 진행한다.

## 배경

기존 UX/IA 스펙은 주요 화면을 아래처럼 정의했다.

- `남기기` -> `/today`
- `답하기` -> `/answer`
- `온설 읽기` -> `/read`
- `내 기록` -> `/me`

하지만 여러 페이지가 생기기 전에 네비게이션 기준을 정하지 않으면, 각 화면이 따로 구현되면서 웹 상단 메뉴, 모바일 하단 탭, 랜딩 로그인 버튼, 내 정보 진입이 서로 다른 방식으로 흩어질 수 있다.

온설의 핵심은 한 화면에 많은 기능을 계속 노출하는 것이 아니라, 사용자가 지금 하려는 행동에 집중하게 하는 것이다. 따라서 네비게이션도 항상 보이는 메뉴 수보다 현재 화면의 집중도를 우선한다.

## 결정 요약

- 랜딩 영역과 서비스 영역의 네비게이션은 분리한다.
- 웹 서비스 화면은 상단 nav를 사용한다.
- 모바일 서비스 화면은 하단 tab을 사용하지 않는다.
- 모바일 서비스 화면은 좌측 상단 메뉴 버튼으로 주요 이동을 연다.
- 로그인 또는 내 정보 진입은 랜딩과 서비스 화면 모두에서 접근 가능하게 둔다.
- `웹에서 시작하기`는 비회원 이용 시작을 의미한다.
- `로그인`은 로그인 후 서비스 이용과 내 기록 보존을 위한 경로다.

## 랜딩 네비게이션

### 역할

랜딩 페이지는 제품 소개와 진입 선택을 담당한다. 서비스 내부 메뉴를 모두 노출하지 않는다. 처음 온 사용자는 온설의 목적을 짧게 이해하고 바로 시작할 수 있어야 한다.

### 진입 경로

랜딩의 주요 진입은 두 가지다.

```text
랜딩페이지 -> 웹에서 시작하기 -> 비회원 서비스 이용
랜딩페이지 -> 로그인 -> 서비스 이용
```

`웹에서 시작하기`는 회원가입 없는 이용을 의미한다. 사용자는 로그인하지 않아도 `/today`로 들어가 위로 요청을 작성할 수 있다. 로그인 전 작성 내용은 기존 정책처럼 localStorage에 임시 저장하고, 로그인 후 이어서 제출할 수 있다.

`로그인`은 내 기록, 내가 남긴 답변, 이후 알림 같은 지속 기능으로 이어지는 경로다. 로그인은 첫 이용의 필수 관문이 아니라, 기록을 보존하고 이어 쓰는 선택지다.

### 랜딩 상단 영역

랜딩 상단은 최소한의 항목만 둔다.

- 서비스명: `온설`
- 보조 진입: `로그인`
- 주요 CTA: `웹에서 시작하기`

랜딩 상단에 `남기기`, `답하기`, `온설 읽기`, `내 기록`을 모두 넣지 않는다. 이 항목들은 서비스 영역의 네비게이션에 속한다.

## 서비스 네비게이션

### 공통 메뉴

서비스 영역의 주요 이동 항목은 아래 네 가지다.

- `남기기` -> `/today`
- `답하기` -> `/answer`
- `온설 읽기` -> `/read`
- `내 기록` -> `/me`

`내 기록`은 주요 행동 메뉴와 성격이 다르다. 웹에서는 우측 개인 영역으로 분리하고, 모바일에서는 메뉴 안에 포함하되 로그인 또는 내 정보 진입과 연결한다.

### 웹

웹 서비스 화면은 상단 nav를 사용한다.

권장 구조:

```text
온설 | 남기기 답하기 온설 읽기                         내 기록 / 로그인
```

규칙:

- `남기기`, `답하기`, `온설 읽기`는 주요 서비스 이동으로 묶는다.
- `내 기록` 또는 `로그인`은 우측 개인 영역으로 분리한다.
- 현재 위치는 active 상태로 표시한다.
- 상단 nav는 화면을 과하게 차지하지 않는다.
- 서비스 화면에서 랜딩의 CTA 문구인 `웹에서 시작하기`를 반복하지 않는다.

로그인 상태별 표시:

- 비로그인: 우측에 `로그인`
- 로그인: 우측에 `내 기록`

비로그인 상태에서도 `/me` 자체는 진입 가능하게 둘 수 있지만, 초기 구현에서는 우측 진입 문구를 `로그인`으로 두는 편이 명확하다. 로그인 전 내 기록 화면이 필요해지면, localStorage 기반 임시 기록 안내를 별도 스펙에서 다룬다.

### 모바일

모바일 서비스 화면은 하단 tab을 사용하지 않는다.

이유:

- 온설의 핵심 화면은 짧은 글 작성과 읽기에 집중해야 한다.
- 하단 tab은 항상 보이는 이동 장치라 입력창, toast, 모바일 키보드와 경쟁할 수 있다.
- 온설은 아직 앱 네이티브 패턴보다 웹 프로토타입의 단순한 흐름이 중요하다.
- 사용자가 매 순간 여러 기능을 오가는 서비스보다, 한 화면에서 한 행동에 집중하는 서비스에 가깝다.

모바일 권장 구조:

```text
[메뉴]                                      [로그인/내 기록]

현재 화면의 핵심 내용
```

좌측 상단 메뉴 버튼은 전체 서비스 이동을 연다.

- `남기기`
- `답하기`
- `온설 읽기`
- `내 기록`

우측 상단에는 로그인 또는 내 기록으로 가는 짧은 진입을 둔다.

- 비로그인: `로그인`
- 로그인: `내 기록`

모바일 상단에 전체 nav 항목을 가로로 나열하지 않는다. 사용자는 작은 화면에서 메뉴를 읽는 대신, 필요할 때 메뉴 버튼을 열어 이동한다.

## 랜딩과 서비스 영역 분리

랜딩과 서비스는 같은 브랜드를 공유하지만 같은 nav를 쓰지 않는다.

랜딩:

- 제품의 첫인상과 진입 선택이 목적이다.
- `웹에서 시작하기`와 `로그인`이 핵심이다.
- 서비스 내부 메뉴 전체를 보여주지 않는다.

서비스:

- 사용자의 실제 행동 전환이 목적이다.
- `남기기`, `답하기`, `온설 읽기`가 핵심이다.
- 개인 영역은 `내 기록` 또는 `로그인`으로 분리한다.

이 분리는 나중에 웹에서 앱 다운로드, 앱에서 이어보기, 앱 설치 안내가 생겨도 유지한다. 랜딩은 웹/앱 선택과 소개를 맡고, 서비스 화면은 실제 사용 흐름을 맡는다.

## 라우트 기준

초기 라우트 이름은 기존 UX/IA 스펙을 유지한다.

| 이름 | 경로 | 역할 |
| --- | --- | --- |
| 랜딩 | `/` | 서비스 소개와 진입 선택 |
| 남기기 | `/today` | 오늘 듣고 싶은 말 남기기 |
| 답하기 | `/answer` | 답변이 필요한 온설에 답하기 |
| 온설 읽기 | `/read` | 다른 사람의 온설과 답변 읽기 |
| 내 기록 | `/me` | 내가 남긴 요청과 답변 보기 |
| 로그인 | `/login` 또는 `/auth` | 로그인 시작 |

로그인 경로는 아직 구현 전에 확정하지 않는다. 인증 구현 스펙에서 `login`과 `auth` 중 하나를 결정한다. 네비게이션 문서에서는 사용자에게 보이는 이름을 `로그인`으로 고정한다.

## 구현 경계

이 문서는 네비게이션 구현 PR의 기준이지만, 즉시 모든 화면을 구현하라는 뜻은 아니다.

초기 구현 후보:

- 공통 서비스 nav 컴포넌트
- 랜딩 헤더의 `웹에서 시작하기`, `로그인` 진입
- 모바일 메뉴 버튼과 메뉴 패널
- active route 표시

초기 구현에서 제외:

- 실제 인증
- 로그인 후 사용자 프로필 표시
- 앱 다운로드 또는 웹/앱 선택 화면
- 권한별 메뉴 제어
- 알림, 설정, 닉네임, 배경

## 테스트 기준

네비게이션 구현 시 최소한 아래를 검증한다.

- 랜딩에는 `웹에서 시작하기`와 `로그인`이 보인다.
- 랜딩에는 서비스 내부 메뉴 전체가 노출되지 않는다.
- 웹 서비스 nav에는 `남기기`, `답하기`, `온설 읽기`가 보인다.
- 웹 서비스 nav의 개인 영역에는 비로그인 상태에서 `로그인`이 보인다.
- 모바일 레이아웃에서는 하단 tab을 렌더링하지 않는다.
- 모바일 메뉴 버튼을 열면 `남기기`, `답하기`, `온설 읽기`, `내 기록`으로 이동할 수 있다.
- 현재 라우트는 active 상태로 표시된다.

## 후속 결정 필요 사항

아래 항목은 이번 문서에서 확정하지 않는다. 구현 전에 별도 확인이 필요하다.

- 로그인 라우트를 `/login`으로 할지 `/auth`로 할지
- 비로그인 상태의 `/me`를 localStorage 임시 기록 화면으로 열지, 로그인 유도 화면으로 열지
- 모바일 메뉴 패널을 drawer로 할지 popover로 할지
- 서비스 nav를 #45의 `/today` 구현과 언제 통합할지
- 앱으로 확장할 때 모바일 웹 메뉴와 앱 네이티브 navigation을 어떻게 대응시킬지
